# 푸시업 판정 기준 (측면 촬영 전용)

스쿼트와 **같은 구조**다. 기준 관절각만 무릎 → 팔꿈치로 바뀐다.
공통 개념(왜 측면인가, 왜 최저점 스냅샷으로 판정하는가, 반복 카운트 히스테리시스)은
[CAPTURE_AND_SQUAT_CRITERIA.md](./CAPTURE_AND_SQUAT_CRITERIA.md)에 있고 여기서 중복하지 않는다.

기준 코드: `ai/analysis/exercises/pushup.py`, `ai/analysis/exercises/base.py`, `ai/config.py`

> ⚠️ **아래 임계값은 전부 관례적 기본값이며 실영상으로 검증되지 않았다.**
> 푸시업 영상이 하나도 없는 상태에서 규칙과 단위 테스트만 먼저 만든 것이다.
> 검증 절차는 [PENDING_VIDEO_WORK.md](./PENDING_VIDEO_WORK.md).

## 1. 촬영

| 항목 | 권장 | 이유 |
|---|---|---|
| 카메라 위치 | 몸의 **정옆**, 몸의 좌우축과 렌즈축이 수직 | 순수 시상면 → 팔꿈치각/몸통 선 왜곡 최소 |
| 카메라 높이 | **어깨~바닥 사이**(가급적 낮게), 지면과 수평 | 서서 내려다보면 팔꿈치각과 몸통 선이 함께 눌린다 |
| 거리 | 머리부터 발끝까지 여유 있게 들어오는 거리 | 몸이 가로로 길어 스쿼트보다 넓은 화각이 필요하다 |
| 프레이밍 | **발목까지** 잘리지 않게 | 발목이 잘리면 몸통 선이 무릎 기준으로 대체된다(§3.2) |
| 배경/조명 | 균일한 조명, 역광 금지 | 관절 신뢰도(`MIN_KEYPOINT_CONFIDENCE`=0.5)를 넘겨야 계산에 쓰인다 |
| 복장 | 어깨·엉덩이 라인이 드러나는 옷 | 헐렁하면 몸통 선이 흔들려 이탈각이 노이즈 |
| 바닥 | 매트 색과 몸 색의 대비 확보 | 엎드린 자세는 몸-바닥 대비가 낮으면 검출률이 떨어진다 |
| 프레임레이트 | **30 fps 이상** | 푸시업은 최저점 체류가 짧아 놓치기 쉽다 |

머리쪽/발쪽에서 찍은 영상은 팔꿈치각도 몸통 선도 잴 수 없다. 어깨 간격/몸통 길이
비율로 자동 검증해 `not_side_view` 경고를 붙인다(스쿼트와 같은 지표·같은 경계값 0.35).
⚠️ 이 경계값이 푸시업에서도 맞는지는 확인되지 않았다
([PUSHUP_TUNING.md §4](./PUSHUP_TUNING.md)).

## 2. 반복(rep) 카운트

팔꿈치각으로 UP/DOWN을 오가며 **DOWN → UP 전환 1회 = 반복 1회**.

| 전환 | 조건 | 임계값 |
|---|---|---|
| UP → DOWN(내려감) | 팔꿈치각 < `PUSHUP_ELBOW_DOWN_ANGLE` | **130°** |
| DOWN → UP(올라옴, rep+1) | 팔꿈치각 > `PUSHUP_ELBOW_UP_ANGLE` | **160°** |

- 팔을 다 펴면 170~180°, 가슴이 바닥에 가까우면 90° 이하로 접힌다.
- `PUSHUP_PARTIAL_DIP_ANGLE`(**145°**) 아래로 내려갔지만 130°까지 못 간 움직임은
  rep으로 세지 않고 `partial_rep_count`로 따로 집계한다.
- 각도 시계열은 중앙값 필터(`PUSHUP_ANGLE_SMOOTH_WINDOW`=3)로 평활화한다.

## 3. 자세 규칙 — 최저점 스냅샷 기준

### 3.1 깊이 — `check_depth`

| 코드 | 조건 | 심각도 |
|---|---|---|
| `good_depth` | 최저 팔꿈치각 ≤ `PUSHUP_GOOD_DEPTH_ANGLE`(**90°**) | GOOD |
| `shallow_depth` | 90° 초과 ~ `PUSHUP_SEVERE_DEPTH_ANGLE`(**110°**) 이하 | WARNING |
| `very_shallow_depth` | 110° 초과 | ERROR |

- 근거: "팔꿈치 90° 이하까지 내려간다"가 통용되는 기준. **관례값이며 미검증.**
- 코드 이름은 스쿼트와 공유한다(같은 '깊이' 축이라 백엔드 매핑이 하나로 끝난다).
  문구는 운동별로 다르다("허벅지가 바닥과 수평" vs "팔꿈치가 직각").
- 경계값은 아래 단계에 속한다(초과일 때만 승급).

### 3.2 몸통 일직선 — `check_body_line`

어깨-엉덩이-발목이 이루는 각이 180°에서 벗어난 정도(**이탈각**)로 판정한다.

| 코드 | 조건 | 심각도 |
|---|---|---|
| (없음) | 이탈각 ≤ `PUSHUP_BODY_LINE_WARN`(**15°**) | — |
| `body_line_break` | 15° 초과 ~ `PUSHUP_BODY_LINE_SEVERE`(**25°**) 이하 | WARNING |
| `excessive_body_line_break` | 25° 초과 | ERROR |

- **방향에 따라 교정이 반대**라 문구를 갈라 준다. 엉덩이가 선보다 화면상 아래면
  처짐(허리 부담), 위면 솟음(가동 범위 축소). 방향은 외적 부호가 아니라 **같은 x에서의
  y 비교**로 판단해, 사람이 좌·우 어느 쪽을 보고 있어도 결과가 같다.
- 발목이 안 보이면 **무릎까지**로 대체해 잰다(무릎 대고 하는 푸시업, 발이 프레임 밖).
- 어깨·엉덩이·다리 중 하나라도 안 보이면 판정을 보류한다(값을 지어내지 않는다).
- 몸통 축이 화면상 거의 수직이면(엎드린 자세로 보기 어려움) 방향을 단정하지 않고
  이탈 사실만 알린다.

### 3.3 규칙에서 제외한 것

| 후보 | 제외 이유 |
|---|---|
| 손 간격 / 팔꿈치 벌어짐(flare) | 좌우 정보라 측면에서 관절이 겹쳐 측정 불가 (§3.4) |
| 목 각도(고개 들기) | COCO-17로는 목이 없고, 코·귀만으로는 신뢰도가 낮다 |
| 템포 | 시간 측정이고 rep 경계 추정 정확도에 그대로 의존한다 |
| 팔 폄(lockout) 부족 | 별도 규칙 없이 rep 카운트로 흡수된다. 160°까지 안 펴면 rep이 안 세어지고 부분 반복으로 집계된다 |

### 3.4 위/정면 앵글 전용 규칙 — ⚠️ 미구현(향후)

> 현재 측면 전용 파이프라인에는 없다. 두 번째 앵글을 도입할 때 추가할 후보다.
> 스쿼트의 [정면 전용 규칙](./CAPTURE_AND_SQUAT_CRITERIA.md)과 같은 위치의 설계 메모다.

| 후보 코드 | 잴 수 있는 앵글 | 측정 방법(안) |
|---|---|---|
| `elbow_flare` | 위(머리 위) 또는 머리쪽 | 상완이 몸통 축과 이루는 각. 90°에 가까울수록 어깨 부담 |
| `hand_width` | 위 또는 머리쪽 | 좌우 손목 간격 ÷ 어깨너비 |
| `shoulder_asymmetry` | 머리쪽 | 좌우 어깨 높이 차 — 한쪽으로 미는 습관 검출 |

셋 다 측면에서는 좌우 관절이 겹쳐 측정이 불가능하다.
측면 세트의 깊이·몸통 판정을 신뢰하고, 두 번째 앵글은 보완용으로 쓰는 구성이 된다.

### 3.5 절대 상한 안전장치를 두지 않은 이유

스쿼트에는 `SQUAT_TORSO_LEAN_HARD_MAX`(70°)라는 절대 상한이 있는데 푸시업에는 없다.
주 지표가 상대값이냐 절대값이냐의 차이다 — 근거는
[PUSHUP_TUNING.md §7](./PUSHUP_TUNING.md).

## 4. 측정값 기록

`RepRecord.bottom_body_line_dev`에 최저점 이탈각을 **판정 여부와 무관하게** 남긴다.
정상 rep의 분포를 봐야 15°/25°가 맞는지 검증할 수 있다(스쿼트의
[SQUAT_TUNING.md §3](./SQUAT_TUNING.md)과 같은 이유).
