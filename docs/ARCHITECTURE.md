# 운동 자세 분석 앱 — 아키텍처 이해 문서

> 이 문서는 "왜 이렇게 만드는가"를 이해하기 위한 문서입니다.
> 코드보다 **흐름과 개념**을 먼저 이해하는 것이 목적입니다.

---

## 1. 이 앱이 하는 일 (한 문장)

사용자가 **운동하는 영상**을 올리면, 컴퓨터가 몸의 **관절 위치**를 프레임마다 찾아내고,
관절이 이루는 **각도**를 계산해서, "스쿼트를 몇 개 했는지 / 자세가 올바른지"를 **피드백**으로 돌려준다.

## 1-1. 앱은 3계층으로 나눈다 (현재는 AI만 구현)

```
┌──────────────┐   영상 업로드    ┌──────────────┐   함수 호출     ┌──────────────┐
│  프론트엔드   │ ───────────────► │  백엔드(서버)  │ ───────────────►│   AI 엔진     │
│ (화면·업로드) │ ◄─────────────── │ (API·파일관리) │ ◄─────────────── │ (ai/ 패키지)  │
└──────────────┘   리포트 표시     └──────────────┘   리포트 반환    └──────────────┘
```

- **AI 엔진 (`ai/`)** ← *지금 구현하는 부분.* 영상 경로를 받아 리포트를 돌려주는 순수 파이썬 모듈.
  서버·화면을 전혀 모른다. 진입점은 `ai.analyze_video()` 함수 하나.
- **백엔드 (`backend/`, 예정)**: 업로드 파일을 받아 저장하고 `analyze_video()`를 호출, 결과를 JSON으로 반환.
- **프론트엔드 (`frontend/`, 예정)**: 사용자가 영상을 올리고 리포트를 보는 화면.

이렇게 나누면 AI를 터미널에서 단독으로 시험(`py -m ai.cli 영상.mp4`)할 수 있고,
서버·화면 작업과 서로 방해하지 않는다.

---

## 2. 핵심 아이디어: 영상 → 숫자 → 판단

컴퓨터는 "자세가 좋다/나쁘다"를 직접 볼 수 없습니다. 그래서 3단계로 번역합니다.

| 단계 | 무엇을 하나 | 결과물 |
| --- | --- | --- |
| ① 인식(Perception) | 영상 속 사람의 관절 좌표를 찾는다 | 관절 17개의 (x, y) 좌표 |
| ② 측정(Measurement) | 좌표로 각도·높이 등 물리량을 계산한다 | 무릎각, 엉덩이 높이 등 숫자 |
| ③ 판단(Reasoning) | 숫자를 규칙과 비교해 좋고 나쁨을 판정한다 | 반복 횟수 + 피드백 문장 |

**이 앱의 핵심 통찰**: 자세 분석은 결국 "관절 각도라는 숫자를 언제/어떻게 비교하느냐"의 문제입니다.
AI(YOLO)는 ① 단계만 담당하고, ②③은 우리가 직접 짜는 **규칙 기반 로직**입니다.

---

## 3. YOLO Pose 란?

- **YOLO** = "You Only Look Once", 이미지를 한 번 보고 물체를 찾아내는 빠른 딥러닝 모델.
- **Pose(자세) 버전** = 사람을 찾는 것에 더해, 몸의 **관절 17개**(COCO 표준)를 함께 찍어줍니다.
- 우리는 `ultralytics` 라이브러리로 사전학습된 모델(`yolo11n-pose.pt` 등)을 그대로 불러 씁니다.
  즉, **모델을 학습시키지 않습니다.** 이미 사람 관절을 잘 찾도록 훈련된 모델을 "사용"만 합니다.

### COCO 17 관절 (keypoint) 표준

```
0: 코(nose)          1: 왼눈     2: 오른눈    3: 왼귀     4: 오른귀
5: 왼어깨            6: 오른어깨  7: 왼팔꿈치  8: 오른팔꿈치
9: 왼손목            10: 오른손목 11: 왼엉덩이 12: 오른엉덩이
13: 왼무릎           14: 오른무릎 15: 왼발목   16: 오른발목
```

각 관절마다 `(x, y, confidence)`가 나옵니다.
- `x, y`: 화면에서의 픽셀 위치
- `confidence`: 그 관절을 얼마나 확신하는지 (0~1). 낮으면 무시해야 함(가려짐/흐림).

## 4. 각도는 어떻게 계산하나 (수학 파트)

자세 판단의 90%는 **세 관절이 이루는 각도**로 이뤄집니다.

예: 무릎 각도 = 엉덩이(11) — 무릎(13) — 발목(15) 세 점이 이루는 각.

```
      엉덩이 A
        \
         \  ← 이 각도 θ 를 구한다
          무릎 B
         /
        /
      발목 C
```

벡터 두 개(BA, BC)의 사이각을 코사인 법칙으로 계산합니다.

```
BA = A - B,  BC = C - B
cosθ = (BA · BC) / (|BA| × |BC|)
θ = arccos(cosθ)  → 도(degree)로 변환
```

- 서 있을 때 무릎각 ≈ 170~180° (거의 직선)
- 깊게 앉았을 때 무릎각 ≈ 70~90° (많이 접힘)

이 각도 변화를 시간순으로 보면 스쿼트 한 개의 "내려감→올라옴"이 보입니다.

---

## 5. 반복(Rep) 카운트: 상태 기계(State Machine)

각도만으로 개수를 세려면 "상태"가 필요합니다. 스쿼트는 두 상태를 오갑니다.

```
       무릎각 > 160° (일어선 상태)
   ┌─────────  UP  ◄─────────┐
   │                          │
 내려감                     올라옴
   │                          │
   └─────────► DOWN ──────────┘
       무릎각 < 100° (앉은 상태)

  UP → DOWN → UP 로 한 바퀴 돌면  = 1회 반복(rep) 완료
```

- 임계값(160°, 100°)은 **튜닝 파라미터**입니다. 사람/카메라 각도에 따라 조정.
- 히스테리시스(두 개의 서로 다른 임계값)를 쓰는 이유: 각도가 경계에서 떨릴 때 중복 카운트 방지.

## 6. 피드백 규칙 (예: 스쿼트)

반복을 세는 동안, 각 rep에서 자세 품질도 함께 검사합니다.

**스쿼트는 측면 촬영만 받습니다.** 측면에서 2D로 정확히 잴 수 있는 항목(깊이·상체 앞숙임)만
판정합니다. 좌우 무릎 모임·비대칭은 측면에서 좌우 관절이 겹쳐 측정이 불가능하므로 다루지
않습니다. (근거·촬영 가이드: [CAPTURE_AND_SQUAT_CRITERIA.md](./CAPTURE_AND_SQUAT_CRITERIA.md))

**중요 — 자세는 "가장 깊이 앉은 프레임(최저점)"으로 판정합니다.** 일어선 순간을 재면
상체 숙임이 거의 항상 정상으로 보이기 때문입니다. 그래서 rep 내내 최저 무릎각
프레임의 관절을 붙들어 두었다가, rep이 끝날 때 그 스냅샷으로 아래 규칙을 검사합니다.

| 검사 항목 | 측정 방법 | 나쁜 자세 판정 | 심각도 |
| --- | --- | --- | --- |
| 깊이 부족 | 최저점 무릎각 | > 100° | ⚠️ 경고 |
| 깊이 심각 부족 | 최저점 무릎각 | > 120° (거의 안 앉음) | 🔴 오류 |
| 상체 숙임 | (엉덩이–어깨 기울기) − (발목–무릎 기울기) 차 | > 25° | ⚠️ 경고 |
| 굿모닝 자세 | 위와 같음 + 절대 기울기 상한 | 차 > 35° 또는 상체 > 70° | 🔴 오류 |

그리고 각 rep은 결함을 종합해 한 줄 판정을 받습니다: **🟢 올바름 / 🟡 교정 필요 / 🔴 잘못됨**
(오류가 하나라도 있으면 '잘못됨', 경고만 있으면 '교정 필요', 없으면 '올바름').
이 판정은 `Report.rep_verdicts()`로 나오고 `to_dict()`에 함께 실려 API가 그대로 내려줄 수 있습니다.

이 규칙들은 `analysis/exercises/squat.py`에 순수 함수(`check_depth`, `check_torso`)로 모여 있어
단위 테스트가 쉽고, **운동마다 파일 하나씩** 추가하면 확장됩니다. 임계값은 `ai/config.py`에 모여
있습니다. (정면 전용 규칙인 무릎 모임·비대칭은 정면 촬영을 도입할 때 추가할 수 있습니다.)

## 7. 폴더 구조와 각 파일의 역할

```
thepict/
├── ai/                        # ★ AI 엔진 (지금 구현 완료) — 독립 파이썬 모듈
│   ├── __init__.py            #   analyze_video 를 공개
│   ├── engine.py              #   ★ 공개 진입점: analyze_video(영상) → 리포트
│   ├── cli.py                 #   터미널 단독 실행: py -m ai.cli 영상.mp4
│   ├── config.py              #   모델 경로, 임계값 등 설정 한곳에 모음
│   │
│   ├── pose/                  # ① 인식 담당
│   │   ├── keypoints.py       #   COCO 17관절 이름·인덱스 상수
│   │   └── detector.py        #   YOLO 모델 래퍼 (프레임 → 관절좌표)
│   │
│   ├── analysis/              # ②③ 측정·판단 담당
│   │   ├── geometry.py        #   각도 계산 등 순수 수학 함수
│   │   ├── feedback.py        #   Issue/Report 데이터 구조 (+to_dict)
│   │   └── exercises/
│   │       ├── __init__.py    #   운동 레지스트리 (create_analyzer)
│   │       ├── base.py        #   모든 운동이 공유하는 분석기 뼈대
│   │       └── squat.py       #   스쿼트 전용 규칙 + rep 카운트
│   │
│   └── video/                 # 입출력 담당
│       └── annotator.py       #   프레임에 관절·뼈대 그리기
│
├── backend/                   # (예정) 서버: 업로드 받고 ai 호출, JSON 반환
├── frontend/                  # (예정) 화면: 업로드·리포트 표시
│
├── tests/                     # AI 로직 검증
│   ├── test_squat_logic.py    #   YOLO 없이 각도·카운트 검증(가짜 좌표)
│   └── smoke_detector.py      #   YOLO 로드·추론 스모크 테스트
│
├── docs/
│   ├── ARCHITECTURE.md        # (이 문서) 개념 이해
│   └── PROGRESS.md            # 진행 로드맵 / 완료 체크리스트
│
├── models/                    # YOLO 가중치(.pt) 저장 (yolo11n-pose.pt)
├── data/output/              # 주석 영상 등 결과물
└── requirements.txt           # 파이썬 의존성 목록
```

**설계 원칙**: "인식 / 측정 / 판단 / 입출력"을 폴더로 분리했습니다.
→ 나중에 YOLO를 다른 모델로 바꿔도 `pose/`만 손대면 되고,
  새 운동(푸시업 등)을 추가해도 `exercises/`에 파일 하나 + 레지스트리 한 줄만 늘리면 됩니다.

### 실행 방법 메모 (Windows)

- 이 PC에서는 `python`이 Microsoft Store 스텁이라 동작하지 않는다. **`py` 런처**를 쓴다.
- 한글/이모지 출력이 깨지면 `$env:PYTHONUTF8="1"` 를 먼저 설정한다.

```powershell
$env:PYTHONUTF8="1"
py -m tests.test_squat_logic     # 로직 검증(빠름, 모델 불필요)
py -m tests.smoke_detector       # YOLO 연동 확인
py -m ai.cli data\sample.mp4     # 실제 영상 분석
```

## 8. 데이터가 흐르는 모습 (엔드투엔드)

```
[사용자] 영상 업로드 (main.py)
    │
    ▼
[video/processor] 프레임을 한 장씩 꺼냄  ──►  numpy 이미지(H×W×3)
    │
    ▼
[pose/detector] YOLO에 프레임 투입      ──►  관절 17개 (x,y,conf)
    │
    ▼
[analysis/geometry] 무릎·엉덩이 각도 계산 ──►  각도 숫자들
    │
    ▼
[analysis/exercises/squat] 상태기계로   ──►  rep 카운트 + 자세 결함 목록
 카운트 + 규칙 검사
    │
    ▼
[analysis/feedback] 결함을 문장으로 정리 ──►  피드백 리포트
    │
    ▼
[video/processor] 관절선을 프레임에 그림 ──►  주석 영상 저장
    │
    ▼
[main.py] 리포트 + 주석 영상 화면에 표시
```

## 9. 지금은 하지 않는 것 (의도적 단순화)

- **여러 사람 동시 분석 안 함**: confidence 가장 높은 1명만.
- **3D 자세 추정 안 함**: 화면상의 2D 각도만. (측면 촬영을 권장하는 이유)
- **모델 재학습 안 함**: 사전학습 YOLO를 그대로 사용.
- **실시간 웹캠 안 함(1차)**: 먼저 "업로드된 영상 파일" 처리부터.

이 단순화들은 나중에 단계적으로 걷어낼 수 있으며, `PROGRESS.md`에 확장 항목으로 적어둡니다.
