# 입력 이상 대응 (영상 분석)

임의의 영상이 들어와도 분석은 예외 없이 끝나고 리포트가 나온다.
이 문서의 목적은 **"틀린 값을 조용히 내지 않는다"** 는 원칙을 어떻게 지키는지 정리하는 것이다.

핵심 규칙 세 가지:

1. 분석이 영상 전체를 못 봤으면, 그 사실을 리포트에 남긴다 (`video_issues`).
2. 재지 않은 값은 지어내지 않는다. 못 잰 rep은 판정 없이 폐기한다.
3. 프레임 하나의 실패가 영상 전체 분석을 죽이지 않는다.

관련 코드: `ai/engine.py`(영상 읽기·추론), `ai/analysis/exercises/base.py`(유실·끊김 대응),
`ai/analysis/exercises/squat.py`·`pushup.py`(판정), `ai/config.py`(임계값)

유실 구간 처리와 상태기계는 `base.AngleRepAnalyzer` **한 벌**뿐이라 두 운동이
같은 보증을 받는다. 아래 표에서 `[푸시업]`으로 표시한 항목만 운동 고유다.

---

## 1. 대응 현황

| 입력 이상 | 처리 | 리포트 코드 |
|---|---|---|
| 사람이 안 잡히는 프레임 | 그 프레임만 건너뜀, 상태 유지 | — |
| 다리 관절 신뢰도 < 0.5 | 각도 계산에서 제외 (프레임 스킵) | — |
| 좌표가 한 프레임 튐 | 중앙값 필터(3프레임)로 제거 | — |
| 사람 검출률 < 50% | 결과 신뢰도 경고 | `low_detection` |
| **영상 파일 손상 (중간 디코딩 실패)** | **최대 5프레임까지 건너뛰며 재시도, 그래도 실패하면 종료. 선언 프레임 수의 90% 미만만 읽었으면 경고** | `truncated_video` |
| **추론(YOLO) 예외** | **프레임 단위로 격리 → 그 프레임만 유실 처리. 실패율 2% 초과 시 경고** | `inference_error` |
| **관절 유실 0.5초 초과** | **진행 중이던 rep 폐기, 중앙값 필터 리셋, 선 자세를 다시 볼 때까지 카운트 중단** | `tracking_gap` |
| 앉은 상태로 영상 종료 | 마지막 1회가 빠졌음을 안내 | `ended_mid_rep` |
| 덜 앉았다 일어남 | rep에서 제외, 별도 집계 | `partial_reps` |
| 정면 촬영 | 어깨간격/몸통길이 비율로 감지 | `not_side_view` |
| fps 메타데이터 이상 | 1~240 범위 밖이면 30으로 대체 | — |
| 배경에 다른 사람 | 직전 프레임 무게중심 최근접으로 대상 고정 | — |
| **[푸시업] 발목 미검출** | **몸통 선을 무릎까지로 대체해 잰다(무릎 대고 하는 푸시업·발이 프레임 밖)** | — |
| **[푸시업] 다리 전체 미검출** | **rep은 세되 몸통 판정은 보류(측정값도 `None`)** | — |

굵은 항목이 이번에 추가된 처리다.

## 2. 추가된 처리 상세

### (a) 디코딩 중단 — `truncated_video`

전에는 `cap.read()`가 False를 주면 즉시 종료했다. 영상 끝인지 중간 손상인지 구분하지
않아서, 10초 영상을 3초만 읽고 멈춰도 "3초짜리 정상 영상"으로 리포트가 나왔다.

- 읽기 실패 시 최대 `VIDEO_READ_RETRY_LIMIT`(5) 프레임을 건너뛰며 재시도한다.
  중간에 몇 프레임만 깨진 영상은 그대로 끝까지 분석된다.
- 종료 후 실제로 읽은 프레임 수를 컨테이너가 선언한 총 프레임 수와 대조한다.
  `VIDEO_TRUNCATION_RATIO`(0.9) 미만이면 조기 종료로 보고 경고를 붙인다.
- 총 프레임 수가 0/음수인 영상(스트림·메타데이터 없음)은 비교가 불가능해 판단을 보류한다.

### (b) 추론 예외 격리 — `inference_error`

`detector.detect()`를 `try/except`로 감싼다. 실패한 프레임은 **사람이 안 잡힌
프레임과 같게** 취급되므로 아래 (c)의 유실 처리에 자연스럽게 흡수된다.
실패 비율이 `MAX_DETECT_FAILURE_RATIO`(2%)를 넘으면 영상 수준 경고를 붙인다.

### (c) 유실 구간 상한 — `tracking_gap`

전에는 100프레임이 비어도 "없던 시간"으로 이어붙였다. 그 결과:

- 최저점 근처가 유실되면 더 얕은 각이 최저점으로 기록돼 **깊이 부족 오판**
- 내려갔다 올라온 구간 전체가 유실되면 **rep이 경고 없이 사라짐**
- 중앙값 필터가 유실 전/후 프레임을 이웃으로 섞음

이제 마지막으로 무릎각을 잰 프레임과의 간격이 `MAX_TRACKING_GAP_SEC`(0.5초, fps
기준 환산)를 넘으면 끊김으로 보고:

1. 진행 중이던 rep을 폐기한다 (`dropped_rep_count` 증가). 판정도 붙이지 않는다 —
   최저점을 못 본 rep에 깊이 점수를 매기는 것은 값을 지어내는 일이다.
2. 중앙값 필터를 비운다.
3. **완전히 선 자세(무릎각 > 160°)를 다시 볼 때까지** 카운트를 재개하지 않는다.
   끊김 중에 이미 앉아 있었다면 내려가는 구간을 못 본 rep이므로 셀 수 없다.
4. 서 있는 동안 난 끊김은 다음 프레임에서 바로 해제되므로 rep 손실이 없다.

리포트에 `tracking_gap_count`, `dropped_rep_count`가 숫자로 남는다.

## 3. 남아 있는 위험

| 항목 | 내용 | 상태 |
|---|---|---|
| 운동 종류 미검증 | 무릎각이 140↔160을 오가기만 하면 걷기·의자에서 일어나기도 rep으로 센다. 측면 여부는 검증하지만 "스쿼트인가"는 검증하지 않는다. 푸시업도 같다 — 팔꿈치각만 오르내리면 무엇이든 센다 | 미해결 |
| NaN 각도 | 관절 좌표가 완전히 겹치면 `angle_at`이 NaN을 반환하고, NaN은 모든 비교가 False라 상태기계가 그 이후 멈출 수 있다 (신뢰도 0.5 이상이면서 좌표가 겹쳐야 해 매우 드묾) | 미해결 |
| 끊김 직후 첫 rep | 끊김 이후 첫 rep은 필터 표본이 1~2개뿐이라 평활 효과가 약하다 | 허용 |
| 선언 프레임 수 오류 | 컨테이너가 총 프레임 수를 틀리게 적은 영상은 `truncated_video` 오탐이 날 수 있다. 그래서 90%로 여유를 뒀다 | 허용 |
